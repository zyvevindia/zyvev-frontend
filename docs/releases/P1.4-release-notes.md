# P1.4 Release Notes — Production Quality Visual Regression

**Release:** P1.4  
**Recommended tag:** `v1.4-production-quality-visual-regression`  
**Type:** Test infrastructure & CI — **no product functionality changes**

---

## Summary

P1.4 delivers a production-grade visual regression testing framework integrated into CI, with Linux GitHub Actions as the authoritative baseline environment. Functional Playwright E2E tests were stabilized for deterministic CI execution. This release improves release confidence and cross-browser layout validation without modifying user-facing product behavior.

---

## New capabilities

### Visual regression testing

- Playwright native `toHaveScreenshot` snapshots for **14 public pages**
- **168** visual tests: 4 viewports × 3 browsers × 14 pages
- Baseline inventory verification (`scripts/verify-visual-baselines.mjs`)
- Deterministic stabilization helpers (fonts, animations, catalog stub, scroll, masks for loading UI only)

### Cross-browser validation

- Chromium, Firefox, and WebKit on Linux CI
- Full browser matrix enforced in `ci.yml` and `visual-linux-baselines.yml`

### Responsive validation

- Desktop (1440×900), laptop (1280×800), tablet (820×1180), mobile (390×844)
- Touch emulation on tablet and mobile viewports

### CI integration

- `.github/workflows/ci.yml` — build, smoke suites, functional E2E, visual inventory check, visual regression
- 120-minute job timeout for full matrix
- Playwright report artifacts on failure

### Linux canonical baseline workflow

- `.github/workflows/visual-linux-baselines.yml` — workflow_dispatch
- Generates Chromium, Firefox, and WebKit baselines on `ubuntu-latest`
- Validates 168 PNGs, re-runs visual suite, uploads `linux-visual-snapshots` artifact
- **Windows snapshots must not become production baselines**

### Deterministic Playwright framework

- Shared `tests/fixtures.js` with catalog API stub for functional E2E (no live backend required)
- `tests/helpers/visualHelpers.js` for visual-only stabilization
- `playwright.config.js` — separate visual and functional projects, `retries: 0` for determinism
- NPM scripts: `test:visual`, `test:visual:update`, `test:visual:verify`, `test:visual:verify:strict`

## Known operational follow-up

1. **Linux baseline generation required** — Current repository may contain Windows-generated Chromium/Firefox PNGs (112/168) and zero WebKit baselines. Run **Visual Linux baselines** workflow, download `linux-visual-snapshots`, replace all snapshot PNGs, and commit before visual CI gate passes.

2. **P1.4 commit hygiene** — Ensure P1.4 test/CI changes are committed separately from unrelated working-tree edits (SEO data, catalog acquisition, etc.).

3. **Post-merge verification** — Confirm green CI on Linux after baseline commit before tagging.

## Upgrade / rollout notes

- No deployment steps required for end users.
- Developers on Windows: local `test:visual` skips WebKit; use Linux CI for authoritative results.
- After intentional UI changes: regenerate baselines on Linux only, then commit updated PNGs.
