# EVSavari v2.0.1 — Media Foundation

**Release ID:** R-MEDIA
**Release name:** Media Foundation Release
**Planned tag:** `v2.0.1-media-foundation`
**Date prepared:** 2026-07-13

## Purpose

Establish reliable local vehicle media for BYD Atto 3, Hyundai Kona Electric,
Mahindra XUV400, and Tata Tiago EV without changing catalog, routing, SEO,
landing, analytics, or backend behavior.

## Business Value

- Replaces low-detail local assets with 1600 px WebP images.
- Keeps provisioned local WebPs ahead of optional image overrides.
- Prevents unprovisioned gallery angles from rendering broken or placeholder
  thumbnails.
- Preserves the existing fallback chain when local media is unavailable.

The 12 replacements increase aggregate asset weight from approximately 95 KB
to 2.59 MB. This release prioritizes visual fidelity and reliable local
delivery, not smaller transfer size. Existing lazy loading limits initial-page
impact for non-eager images.

## Technical Scope

### Resolver changes

- `src/components/media/VehicleImage.jsx`
  - Prioritizes local `/images/cars/` WebPs before optional `src` overrides.
  - Retains the existing loading, responsive source, and fallback behavior.
- `src/utils/vehicleMedia.js`
  - Omits gallery slots that are not provisioned for partial local families.
  - Filters fallback SVGs and placeholders from renderable gallery items.

### Asset changes

The `listing.webp`, `front.webp`, and `compare.webp` files are replaced for:

- `byd-atto-3`
- `hyundai-kona-electric`
- `mahindra-xuv400`
- `tata-tiago-ev`

No media manifest is changed. Existing `familyMediaManifest.js` and
`localCarMediaManifest.js` remain the complementary production and local asset
manifests.

## Architecture Impact

- Media remains a single engine centered on `src/utils/vehicleMedia.js`.
- `VehicleImage.jsx` remains the rendering component for the existing resolver.
- No duplicate resolver, image pipeline, or manifest is introduced.
- No changes to SEO, Landing Framework, Link Graph, Analytics, Catalog,
  Routing, Registry, Lead Engine, or backend APIs.

## Production Impact

Affected surfaces include:

- Vehicle detail hero and gallery: `/cars/:slug`
- Browse/listing cards: `/cars`
- Homepage vehicle cards when an affected family is featured
- Compare pages containing an affected family
- Brand, price, and use-case landing cards containing an affected family

Users should see clearer vehicle photography, stable local image selection,
and no empty gallery thumbnails for unavailable angles. If a local image fails,
the existing Cloudinary/catalog, brand, and final placeholder fallbacks remain
available.

## Known Exclusions

- Media certification scripts and generated certification reports (R-CERT)
- Media audit downloads and screenshots (R-INV/archive)
- Unrelated vehicle families and media manifests
- Analytics, generated SEO data, documentation packages, and all non-media code
- Secrets and Playwright artifacts

### BAT Pass Criteria

1. No browser broken-image icon on any listed URL.
2. Local asset requests return HTTP 200 where provisioned.
3. Non-eager card and gallery images retain `loading="lazy"`.
4. Hero/eager images remain prioritized as before.
5. Image crop and aspect ratio are acceptable at mobile and desktop widths.
6. Forced failure of a local URL advances to an existing fallback rather than
   leaving a blank image.
7. No unprovisioned gallery angle displays a placeholder thumbnail.

## Rollback Plan

Revert the R-MEDIA commit. This restores the prior 12 WebPs and resolver order.
The existing Cloudinary/catalog and placeholder fallbacks remain available
during rollback. No database, environment, routing, or schema rollback is
required.
